BNO08x Driver¶

A C++20 driver for the CEVA BNO080, BNO085 and BNO086 smart sensor hubs. It speaks SHTP and SH-2 over I2C, SPI and UART, and the stand-alone UART-RVC mode, on any MCU, with no heap and no blocking call.

Quickstart API guide Source on GitHub

The BNO08x is a 9-axis sensor hub in one package: an accelerometer, a gyroscope and a magnetometer with a Cortex-M0+ that runs the sensor fusion and reports finished orientation, motion and activity results to the host (Title page, p. 1).

Where it is used¶

  • Sensor hub of a mobile device: always-on activity, gestures and dead reckoning (1.1.1, p. 8)
  • Head tracker of a VR or AR headset (1.1.2, p. 8)
  • Unmanned ground robot (1.1.3, p. 9)

Uses named by the datasheet (Title page, p. 1).

Smart sensor hub BNO080, BNO085, BNO086 CEVA
Function
Accelerometer, gyroscope and magnetometer fused by the MotionEngine into rotation vectors, motion and activity reports
Interface
I2C (0x4A or 0x4B), SPI mode 3 up to 3 MHz, UART-SHTP at 3 Mbit/s, or UART-RVC at 115200 baud; chosen by two strap pins at reset
Reports
Every sensor report of the SH-2 reference manual, batched and timestamped, from 1 Hz to 1 kHz
Configuration
Calibration, tare, orientation and the flash record store (FRS), read and written by record
Supply
VDD 2.4 V to 3.6 V, VDDIO 1.7 V to 3.6 V

Quick start¶

Wire the chip as above, write the port for your MCU (Porting), then:

void RunSensor() {
  static MyPort port;
  static bno08x::Bno08x<MyPort> hub(port); // no I/O yet

  const bno08x::Config cfg{}; // BNO085 on I2C 0x4A
  if (const auto r = hub.Begin(cfg); !r.ok()) {
    std::printf("Begin: %s\n", bno08x::ToString(r.error));
    return;
  }

  bool requested = false;
  for (;;) {
    hub.Poll(port.NowUs()); // every few milliseconds: reads, writes and time-outs all happen here
    if (hub.Ready() && !requested) {
      bno08x::FeatureConfig fc{};
      fc.interval_us = 20000; // 50 Hz
      requested = hub.SetFeature(bno08x::SensorId::RotationVector, fc).ok();
    }
    bno08x::Event e{};
    while (hub.PopEvent(e)) {
      if (e.kind == bno08x::EventKind::Sensor) {
        const auto eu = bno08x::ToEulerCentiDeg(e.v[0], e.v[1], e.v[2], e.v[3]);
        std::printf("yaw %" PRId32 " pitch %" PRId32 " roll %" PRId32 " (centi-degrees)\n",
                    static_cast<int32_t>(eu.yaw), static_cast<int32_t>(eu.pitch),
                    static_cast<int32_t>(eu.roll));
      }
    }
  }
}

From docs/hardware.yml; kokeb-docs hardware --check confirms that every API name is in inc/bno08x.hpp, inc/bno08x_types.hpp, inc/bno08x_euler.hpp and every register (the header constant in brackets, where the header spells it otherwise) in inc/bno08x_registers.hpp.

The driver has no platform code. You give it a small class that moves bytes on your bus and reads a pin or two; it does the rest: the start-up handshake, SHTP framing and its checks, the SH-2 reports and commands, timestamps, calibration, tare and the configuration records.

What you get¶

  • One object, four transports. Bno08x<YourPort> takes a port that names its transport; the I2C, SPI, UART-SHTP and UART-RVC paths share the same API. See Transports.
  • Never blocks. Begin() starts a session and Poll() does all the work in small steps. Operations return an OpId and finish with an event. See Architecture.
  • Every sensor report decoded. One event type with the report's values in its own units, a timestamp and the accuracy. See Sensors.
  • Calibration, tare and FRS. Typed calls for every command of the manual, and generic record read and write. See Calibration.
  • Strict where the documents are, tolerant where they are not. Every place the documents disagree or are silent is a named ambiguity with a configuration knob. See Ambiguities.
  • No heap, no exceptions, no RTTI. Buffers are template parameters. See Contract.
  • Tested without hardware. Host tests run the driver against an independent model of the hub on all four transports, and a fuzzer corrupts what the hub sends. See Testing and CI.
