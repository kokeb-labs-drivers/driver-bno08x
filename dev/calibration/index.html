Calibration and orientation¶

How to make the hub's output accurate and keep it that way: the motion engine's calibration, saving it, tare and reorientation, and the flash records behind them. Every call returns an OpId and finishes with an OpDone event (API guide).

Dynamic calibration¶

The motion engine calibrates the accelerometer, gyroscope and magnetometer while the board moves. Each sensor reports its state as an accuracy (Accuracy::Unreliable to High) on every sample, and a rotation vector also carries an estimated angular error. The calibration guides describe the movements that bring each sensor to high accuracy; nothing in the driver speeds them up.

ConfigureMeCal(MeCal) chooses which sensors calibrate (accel, gyro, mag, and the planar and on_table variants); GetMeCal() returns the current enables in the OpDone values. SaveDcd() writes the calibration data to flash so the next start begins calibrated, SetPeriodicDcd(true) has the hub do that on its own, and ClearDcdAndReset() throws it away and restarts the hub. The periodic-save flag is inverted in the protocol (0 enables); the API takes a plain bool (A35).

bno08x::Error CalibrateAndSave(Hub& hub) {
  bno08x::MeCal cal{};
  cal.accel = true;
  cal.gyro = true;
  cal.mag = true;
  if (const auto r = hub.ConfigureMeCal(cal); !r.ok()) {
    return r.error;
  }
  // ... wait for its OpDone, rotate the board until the accuracy reaches High, then:
  return hub.SaveDcd().error;
}

Tare and reorientation¶

A tare declares the current pose to be the reference. Tare(AxisMask, TareBasis) takes the axes (All or ZOnly; the other masks are refused unless Config::tare_any_mask is set, A37) and the rotation vector the tare is based on. A tare on the game rotation vector reorients only that vector and is not persistent. PersistTare() keeps the last tare over a restart. SetReorientation(Quat14) and ClearReorientation() set the mounting orientation, a fixed rotation applied to every output.

bno08x::Error TareHeading(Hub& hub) {
  if (const auto r = hub.Tare(bno08x::AxisMask::ZOnly, bno08x::TareBasis::RotationVector);
      !r.ok()) {
    return r.error;
  }
  return hub.PersistTare().error; // optional: keep it over a restart
}

Interactive calibration (BNO086)¶

The BNO086 can be told what the host knows about its motion: SetMotionIntent(MotionIntent) with the states unknown, stationary (with or without vibration), in motion and in motion accelerating. The hub asks for the information through sensor 0x2B (MotionRequest), and StartSimpleCal() and FinishSimpleCal() run the simple calibration, whose result is in the finish operation's detail (SimpleCalStatus). On a BNO080 or BNO085 the driver refuses these with Error::Variant while Config::strict_variant is set (A3, A4).

Records in flash (FRS)¶

The hub keeps its configuration in numbered records. ReadFrs(record, FrsBuffer&) fills a caller-owned buffer of up to kFrsMaxWords words, which must stay valid until the OpDone event; WriteFrs() writes words and, with Config::frs_verify, reads them back; EraseFrs() erases. One FRS operation runs at a time (A29). A write is complete at status 3; status 12 means the memory is full (A26, A27). Reads send zero in the reserved bytes (A28). Sensor metadata (ReadMetadata, GetMetadata) lives in per-sensor records and is parsed in both layout revisions (A30).

bno08x::Error ReadOrientationRecord(Hub& hub) {
  static bno08x::FrsBuffer buffer;          // must stay valid until the OpDone event
  return hub.ReadFrs(0x2D3E, buffer).error; // the words are in `buffer` when the operation finishes
}

Writing a record the driver does not describe can change how the hub behaves in ways only a restart undoes. Use the typed calls above where one exists.
